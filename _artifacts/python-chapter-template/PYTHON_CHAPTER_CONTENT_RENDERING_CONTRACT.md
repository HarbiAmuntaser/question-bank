# Python Chapter Content Rendering Contract

هذا العقد مرجع ثابت لـ`PY-02 – Python – إنتاج المحتوى والفصول`. طبّقه على كل فصل قبل تسليم ملفات الإنتاج.

## 1. Questions: صيغة المحتوى

حقول `questionText` و`options[].text` و`explanation` تستخدم نصًا عاديًا مع دعم تنسيق خفيف للكود. لا تستخدم HTML داخل هذه الحقول.

### Inline code

ضع backticks مفردة حول العنصر البرمجي المضمن داخل جملة عربية:

- الدوال واستدعاءاتها: `input()` و`print(value)`.
- أسماء المتغيرات والمعرّفات: `student_name`.
- الأنواع والقيم: `int` و`True` و`None` و`"Python"` و`25`.
- العوامل عندما تكون موضوع العبارة: `==` و`//` و`**`.
- التعبير القصير: `7 // 2`.

مثال صحيح:

```text
ما نوع القيمة التي تعيدها `input()` مباشرة؟
```

لا تترك العنصر التقني بلا backticks عندما يكون تمييزه ضروريًا لفهم السؤال.

### Python code blocks

كل كود Python مستقل أو متعدد الأسطر داخل `questionText` يجب أن يوضع داخل fenced code block بمعرّف `python`. يجب أن يفصل سطر فارغ بين نص السؤال وكتلة الكود.

مثال صحيح عند كتابة النص:

````text
ما ناتج الكود التالي؟

```python
name = "سارة"
print(name)
```
````

وعند إنتاج JSON يجب تمثيل الأسطر باستخدام `\n`:

```json
{
  "questionText": "ما ناتج الكود التالي؟\n\n```python\nname = \"سارة\"\nprint(name)\n```"
}
```

استخدم language identifier بقيمة `python` لكود Python، واستخدم `text` فقط عندما تكون الكتلة ناتج تشغيل أو نصًا غير تنفيذي.

معرّف اللغة يعرض اسم اللغة أعلى كتلة الكود، لكنه لا يبرر ترك الكود بلا fences ولا يُفترض أنه يضيف syntax highlighting.

### قواعد إضافية للأسئلة

- طبّق inline backticks أيضًا داخل الخيارات والشروحات عند وجود مصطلحات برمجية.
- يمكن إبقاء الجملة العربية RTL؛ كتل الكود وinline code ستظهر LTR عند استخدام الصيغة المعتمدة.
- لا تستخدم المسافات البادئة وحدها لإنشاء كتلة كود.
- لا تضع كودًا متعدد الأسطر بعد السؤال كنص عادي.
- لا تستخدم HTML أو `<pre>` أو `<code>` داخل JSON الخاص بالأسئلة.
- لا تستخدم backticks مفردة حول نص يمتد على أكثر من سطر؛ استخدم fenced code block.

## 2. StudySummary: صيغة contentHtml

`contentHtml` هو HTML وليس Markdown. لا تستخدم Markdown backticks أو fenced code blocks داخله.

### Inline code في الملخص

استخدم `<code>...</code>` للدوال والمعرّفات والأنواع والقيم والعوامل والتعبيرات القصيرة داخل النص العربي.

مثال صحيح:

```html
<p>تعيد الدالة <code>input()</code> قيمة من نوع <code>str</code>.</p>
```

### Code blocks في الملخص

كل مثال Python مستقل أو متعدد الأسطر يستخدم:

```html
<pre dir="ltr"><code>name = input("الاسم: ")
print(name)</code></pre>
```

- يجب أن يحمل كل `pre` الخاص بالكود `dir="ltr"`.
- يبقى الشرح العربي خارج `pre` حتى يظل RTL.
- اهرب الرموز الحساسة داخل HTML عند الحاجة: `<` تصبح `&lt;`، و`>` تصبح `&gt;`، و`&` تصبح `&amp;`.
- لا تضف `class` خاصًا بلغة Python؛ التنسيق العام يكفي.

### بقية عناصر الملخص

- مقدمة مباشرة بلا `h1`.
- `h2` للأقسام الرئيسية و`h3` للأقسام الفرعية.
- `ul` و`ol` للقوائم.
- الجداول تستخدم `table` و`thead` و`tbody` و`tr` و`th` و`td`.
- لا تستخدم `script` أو `iframe` أو `style` أو inline style أو event handlers.
- لا تغيّر اتجاه المحتوى كله إلى LTR؛ النص العربي يبقى RTL والكود وحده LTR.

## 3. أخطاء ممنوعة

- كود Python متعدد الأسطر داخل `questionText` من دون fenced code.
- دالة أو معرف مهم داخل سؤال بلا inline backticks.
- استخدام Markdown backticks داخل `contentHtml` بدل `<code>`.
- وضع مثال متعدد الأسطر في `<p>` داخل StudySummary.
- استخدام `<pre>` بلا `dir="ltr"`.
- وضع الشرح العربي داخل كتلة الكود.
- افتراض وجود syntax highlighting أو إضافة CSS/JavaScript إلى المحتوى.
