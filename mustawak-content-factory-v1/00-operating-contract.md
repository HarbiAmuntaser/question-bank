# 00 — عقد التشغيل

## 1. الهدف

إنتاج فصل جامعي كامل من مصادر محددة، مع مخرجات قابلة للمراجعة والنسخ إلى لوحة مستواك، ومنع خلط المصادر أو اعتماد محتوى غير موثق.

## 2. الوحدات التشغيلية

- **التخصص:** مجلد محلي جامع، وليس وحدة سياق إلزامية في ChatGPT.
- **المادة:** وحدة العزل والإنتاج الأساسية.
- **الفصل:** وحدة التنفيذ والإصدار المتكرر.
- **الإصدار:** حزمة فصل اجتازت التدقيق ويمكن إدخالها كمسودة في الإدارة.

### اختيار Project أو Chat

- استخدم مشروعًا مستقلًا للمادة عندما تكون مصادرها كثيرة، أو تستمر مدة طويلة، أو تتطلب تعليمات خاصة.
- يمكن وضع المواد الصغيرة في مشروع تخصص واحد، مع محادثة منفصلة لكل مادة وعدم مشاركة مصادر مادة في محادثة أخرى.
- اجعل المحادثة الرئيسية واحدة للمادة ما دام السياق منضبطًا.
- محادثة التدقيق المستقلة مطلوبة عند الإصدار، ويمكن إغلاقها بعد حفظ تقريرها محليًا.
- لا تعتمد على Project memory وحدها؛ أعد تمرير بطاقة المادة ودفتر الإنتاج عند استئناف العمل.

## 3. دور GPT الخاص

يجوز استخدام GPT خاص `Only me` كبوابة بدء اختيارية لتوحيد التعليمات الثابتة والمطالبة المختصرة. لا يجوز أن يكون:

- مخزنًا وحيدًا للعقود أو المصادر.
- بديلًا عن ملفات الحزمة المحلية.
- مصدرًا لحقائق أكاديمية غير موجودة في المصادر.
- شرطًا لتشغيل المصنع.

عند استخدامه، تُلصق مواصفات `mustawak-spec-bundle.md` في تعليماته، وتبقى بطاقة المادة والمصادر داخل مشروع/محادثة المادة.

## 4. المدخلات الإلزامية قبل الإنتاج

1. بطاقة مادة مكتملة من `templates/subject-brief.yaml`.
2. سجل مصادر من `templates/source-manifest.csv`.
3. ملفات المصادر المحلية أو مقتطفاتها، مع ترقيم صفحات/شرائح يمكن الرجوع إليه.
4. قرار نوع الملخص: `print_attachment` أو `platform_html`، أو `hybrid` بموافقة صريحة.
5. سياسة لغة المادة والأسئلة والشرح.
6. تخطيط كامل للفصول قبل البدء في إنتاج فصل منفرد.

إذا غاب مصدر أو تضاربت مرجعياته، يتوقف الإنتاج عند سجل `BLOCKED_SOURCE` ولا تُخمن الإجابة.

## 5. دورة الإنتاج المختصرة

### الطلب الأول للمادة

> ابدأ إعداد المادة من بطاقة المادة والمصادر. أنشئ خريطة التغطية وخطة الفصول فقط، ولا تنتج المحتوى قبل عرض التعارضات والفجوات.

المخرج: خريطة مصادر، خطة فصول، مصفوفة أهداف، مخاطر، وأسئلة تحتاج قرارًا.

### طلب إنتاج الفصل

> نفّذ الفصل التالي كاملًا وفق مواصفات Mustawak Content Factory والمصادر المعتمدة، ثم جهّز حزمة النسخ إلى الإدارة. لا تعتمد المحتوى نهائيًا.

المخرج بالترتيب الثابت:

1. بيانات Chapter.
2. بيانات StudySummary.
3. HTML الملخص في كتلة مستقلة.
4. JSON الأسئلة في كتلة مستقلة.
5. إعداد Quiz.
6. JSON SEO للملخص والاختبار، كل سجل في كتلة مستقلة.
7. Source map.
8. تقرير فحص ذاتي.
9. خطوات الإدخال اليدوي.

### طلب التدقيق المستقل

> دقّق هذه الحزمة كمدقق مستقل. طابق كل ادعاء وكل إجابة مع المصادر، واختبر الغموض والتكرار وتوافق صيغ الاستيراد. لا تصلح بصمت؛ أعد قائمة Findings وقرار PASS/REJECT.

### طلب الإصدار

> طبّق فقط التصحيحات المعتمدة، أعد جميع البوابات، ثم أنشئ release manifest نهائيًا دون إضافة معلومات جديدة.

## 6. حالات العمل

`PLANNED` → `SOURCES_READY` → `DRAFTED` → `SELF_CHECKED` → `INDEPENDENT_REVIEW` → `APPROVED` → `ENTERED_AS_DRAFT` → `PUBLISHED`

حالات مانعة: `BLOCKED_SOURCE`, `REJECTED_ACCURACY`, `REJECTED_FORMAT`, `NEEDS_PRODUCT_DECISION`.

لا يجوز تجاوز `INDEPENDENT_REVIEW` بسبب ارتفاع درجة الجودة؛ أي خطأ في الإجابة الصحيحة أو مخالفة للمصدر يعني `REJECTED_ACCURACY`.

## 7. الأرشفة والإصدارات

- الحفظ محلي فقط؛ لا Google Drive ولا Work كمتطلب.
- يُحفظ كل فصل في مجلد مستقل.
- أسماء الإصدارات: `vMAJOR.MINOR.PATCH`.
- `MAJOR`: تغيير منهج أو مصادر أساسية. `MINOR`: إضافة/إعادة تنظيم معتبرة. `PATCH`: تصحيح بلا تغيير نطاق.
- كل إصدار يملك `release-manifest.yaml` يتضمن hashes أو أسماء الملفات، المصدر، تاريخ المراجعة، والموافق.
- لا تستبدل إصدارًا معتمدًا بصمت؛ احتفظ به في `archive/` أو سجّل supersededBy.
- بعد تحويل HTML إلى PDF، يُثبت رقم النسخة وعدد الصفحات. أي استبدال للـPDF يستلزم إعادة التحقق من كل `reviewPage` المرتبط به.

## 8. قواعد النسخ إلى الإدارة

- اعرض كل حقل قصير كجدول `الحقل | القيمة`.
- ضع HTML وJSON والروابط الطويلة كلٌ في كتلة مستقلة قابلة للنسخ.
- لا تضع UUID وهميًا في حقول تحتاج كيانًا موجودًا؛ اكتب `SELECT_IN_ADMIN`.
- `reviewSummaryId` لا يخرج في JSON الأسئلة؛ يختاره المشرف مرة واحدة عند الاستيراد.
- ابدأ Chapter وQuestion كـ`isActive=false` عند التجربة، وStudySummary كـ`draft`، وSEO بـ`noindex=true` حتى المراجعة النهائية.
- لا تنشر تلقائيًا ولا تنفذ أي كتابة في النظام من هذه الحزمة.

## 9. منع التوسع غير المنضبط

- لا تستخدم الإنترنت أو مرجعًا جديدًا إلا بعد إضافته إلى `source-manifest.csv` واعتماده.
- لا تنتج PDF.
- لا تنشئ HTML كاملًا لمسار `platform_html`.
- لا تفرض كل مكونات قالب A4؛ اختر المكونات التي تخدم المادة.
- لا تغيّر نطاق الدفع أو SEO أو URLs أو قاعدة البيانات.
- لا تعتبر الملفات القديمة مصدر حقيقة إذا خالفت الكود الحالي أو هذه العقود.
