# 06 — بوابات الجودة والإصدار

## 1. مبدأ القرار

الإصدار يحتاج نتيجتين منفصلتين:

1. **Hard gates:** PASS أو REJECT.
2. **Quality score:** لتحسين الجودة بعد سلامة البوابات.

لا تستطيع أي درجة تعويض إجابة خاطئة أو معلومة بلا مصدر أو ملف غير متوافق.

## 2. Gate A — جاهزية المصادر

- كل مصدر له sourceId وحالة approved.
- النسخة والصفحات/الشرائح معروفة.
- لا مصدر مؤقت أو رابط غير متاح هو المرجع الوحيد.
- التعارضات موثقة ومحسومة أو موسومة blocked.
- كل learning objective مرتبط بمصدر واحد على الأقل.

أي فجوة تمس صحة المحتوى = REJECT.

## 3. Gate B — دقة الملخص

- كل ادعاء جوهري قابل للتتبع.
- التعريفات والشروط والاستثناءات لم يتغير معناها.
- الأمثلة والرسومات والنتائج صحيحة.
- لا إضافة من خارج المصادر.
- يغطي الملخص الأهداف المعتمدة ولا يتجاوز scope.
- المصطلحات والترجمة متسقة مع glossary.

## 4. Gate C — الأسئلة

- كل إجابة صحيحة مثبتة مستقلًا.
- لكل MCQ أربعة خيارات افتراضيًا وصحيح واحد بالضبط.
- لا سؤال غامض أو أكثر من إجابة محتملة.
- المشتتات معقولة وغير كاشفة.
- الصعوبة ناتجة عن الطلب المعرفي.
- لا تكرار نصي أو دلالي غير مقصود.
- الشرح واللغة مطابقان لبطاقة المادة.
- reviewTopic/page يطابقان النسخة النهائية.

أي إجابة خاطئة أو غير مثبتة = REJECT للحزمة، لا warning.

## 5. Gate D — التوافق التقني

- JSON الأسئلة parseable وبالحقول المدعومة فقط.
- questionType محصور في MCQ/TF للاستيراد الحالي.
- reviewPage عدد صحيح >=1 أو null.
- لا UUID مختلق ولا reviewSummaryId داخل السؤال.
- SEO سجل واحد وبلا حقول زائدة.
- حدود النصوص والروابط والـslugs سليمة.
- platform HTML fragment بلا script/style/forms/event handlers أو javascript URLs.
- print HTML مستقل ولا يعتمد على موارد غير معتمدة.

## 6. Gate E — A4 والطباعة

- القالب v4.2 وهوية مستواك محفوظان.
- لا قص أو overlap أو overflow أو صفحات بيضاء عرضية.
- الجداول وكتل الكود قابلة للقراءة.
- العربية والإنجليزية واتجاهاتهما سليمة.
- MUSTAWAK.COM رابط فعلي داخل document ويعمل في PDF.
- عدد الصفحات نهائي، وكل reviewPage أعيد فحصه.

## 7. Gate F — SEO والنشر

- العنوان والوصف يعكسان الصفحة بلا claims.
- canonical صحيح أو null قبل اعتماده.
- noindex=true خلال التجربة.
- JSON-LD صالح ومطابق أو null.
- لا رابط خاص أو signed URL في الحقول العامة.

## 8. التدقيق المستقل

يستخدم المدقق المصادر الأصلية والحزمة، ولا يعتمد على تبرير المنتج. يخرج:

- findings مرقمة مع severity: blocker, major, minor.
- مرجع المصدر لكل blocker/major.
- قرار لكل سؤال: accept, revise, reject.
- قرار للحزمة: PASS أو REJECT.
- قائمة تغييرات، لا إصلاحات صامتة.

من أنتج المسودة لا يمنحها PASS النهائي في نفس السياق. يكفي فتح محادثة تدقيق مستقلة واحدة عند إصدار الفصل.

## 9. Quality score

بعد PASS فقط، قيّم من 100:

- fidelity and coverage: 30.
- clarity and pedagogy: 20.
- question quality and variety: 25.
- technical/import readiness: 15.
- visual/SEO consistency: 10.

الحد المقترح للإصدار 85/100، لكنه لا يلغي hard gates.

## 10. الإصدار

قبل الحالة APPROVED:

- كل blocker وmajor مغلق.
- minor مقبول أو مسجل بقرار.
- الملفات النهائية وحدها في manifest.
- version وtemplateVersion وsource versions مثبتة.
- hash أو حجم/تاريخ كل artifact مسجل.
- سجل التغطية وتقرير المدقق محفوظان.

الإدخال إلى لوحة الإدارة يتم كمسودة أولًا، ثم معاينة عامة محمية، ثم نشر بقرار بشري.

## 11. ما بعد الإدخال

تحقق يدويًا من:

- ارتباط Chapter بالمادة الصحيحة.
- Summary بالفصل واللغة والوصول الصحيح.
- عدد الأسئلة المستوردة والمرفوضة والمكررة.
- اختيار reviewSummaryId الصحيح للدفعة.
- Quiz يضم الفصول والعدد المتوقعين.
- SEO مرتبط بالمالك والlocale الصحيحين.
- PDF خاص ولا يكشف URL مباشرًا.

## 12. تغييرات المصدر والـPDF

- تغير المصدر بعد الإصدار يفتح change request وإصدارًا جديدًا.
- استبدال PDF المرتبط بأسئلة يطلق warning إلزاميًا وإعادة فحص كل reviewPage.
- تغيير عنوان section لا يكسر V1 تقنيًا لأنه لا يعتمد على anchors، لكن يجب تحديث reviewTopic إن تغير المعنى.
- لا تعدّل إصدارًا معتمدًا دون تحديث ledger وmanifest.
